\section{Results}

\paragraph{Setup.} Three Debian containers share one systemd slice and one
mounted volume; the sensor runs on the host. Two suites are reported separately
because they answer different questions. The \emph{scripted} suite uses
deterministic actors to exercise the sensor across media and is scored against
ground truth fixed before any run. The \emph{live} suite uses omp agents with a
language model, and exists to produce transcripts: only there can a
transcript-only monitor be compared with the kernel. Episodes are hermetic, each
starting from an empty shared surface, and detector and scenario hashes are
recorded per run.

\paragraph{Storage-channel coverage.} Table~\ref{tab:scripted} summarises 80
episodes over 19 channels: file content (including append, truncate, size change
and delete-then-recreate), inode metadata (xattr, mtime, mode), namespace
operations (directory creation, nested directories, rename, hardlink, symlink),
channel objects (a FIFO and a shared mapping), local sockets, and multi-agent
topologies (a three-hop relay and a one-to-many fan-out). Recall is $88/88$ with
zero false edges; the 95\% lower bound on recall given zero failures is $96.7\%$.

Local sockets are included, and they are worth singling out because they are the
channel a reviewer raises first. An \texttt{AF\_UNIX} socket names its object in
the sockaddr rather than in a path argument, so the probe reads the 2-byte address
family and follows \texttt{sun\_path} only when it is \texttt{AF\_UNIX};
\texttt{bind} creates the socket inode and \texttt{connect} resolves the same
path, which is an ordinary mutator-to-sensor pair. All eight episodes recovered,
including a variant with no cleanup \texttt{unlink}, where \texttt{bind} is the
only mutator.

\paragraph{Transcript-only monitoring fails.} Across all eighteen live episodes
the kernel recorded 42 edges, and a monitor that reads only declared tool calls
recovered none (95\% upper bound on recall given zero detections, $6.9\%$). This
holds in the \emph{laundering} modes, where the agent's declaration is true: it
ran \texttt{pytest -q} or \texttt{npm test}, but the binary answering to that name
had been replaced and performed the covert write. Reconciliation reports
\texttt{match}, both declarations are honest, and the interaction is still
recovered because it is recorded at the object. Oversight that trusts claims fails
not only when agents lie, but when they tell the truth about a name whose
implementation is hostile.

\paragraph{What the model does not cover.} One probe is expected to be missed and
is reported separately. Lock contention carries its payload in the delay one agent
waits while the other holds \texttt{flock}, so by the storage and timing
distinction it is a timing channel that happens to borrow a filesystem object:
neither party changes the file, and the two operations are both mutators, so no
mutator-to-sensor pair exists. Across four probe episodes it produced no edge.
Reporting it separately is the point: a detector that keyed on medium rather than
observable would claim it.

\paragraph{Benign control.} Forty episodes span ten controls: independent work,
randomly generated paths, co-readers of a read-only file, a single agent writing
and reading its own file, interleaved but disjoint writes, subtree reads under
\texttt{/usr/share}, temporary-file churn, and legitimate cache sharing under a
permissive policy. No benign episode produced an unsanctioned edge, nor an edge on
an object outside its declared set; the 95\% upper bound on the per-episode alarm
rate given zero alarms is $7.2\%$. The cache episode does produce edges, which is
the intended behaviour: the mechanism fires and the policy stays quiet.

\paragraph{Colocated agents.} Identity does not require a container per agent. We
partitioned one running container into two agents by creating child cgroups inside
its cgroup and moving each agent's process into one, declaring both to the sensor
out of band. Two processes in that single container, one writing a file on the
shared volume and one reading it, produced an edge between the two declared
identities in 3 of 3 runs, with a handoff interval of 506~ms in the measured run,
and 147 and 148 events attributed to the two identities respectively. Delegation
is therefore not the obstacle; the requirement is that a deployment create the
partition before the agent forks, since cgroup membership is inherited.

\paragraph{Reconciliation results.} On honest transcripts every declaration
matches an execution and no surplus is reported. Rewriting the declared command in
one agent's session file produces one \texttt{mismatch} and an \texttt{unaccounted}
set naming the command that actually ran. The object edge survives both the
rewrite and the subsequent \texttt{unlink}, because the edge is published before
the file is deleted; deletion is recorded as a scrub annotation rather than as a
retraction.

\paragraph{Defects found by the suite.} Seven defects were found by running or by
review rather than by inspection: absolute symlink targets resolved in the host
namespace; rename destinations captured but never correlated; a global
path-to-inode cache that let one agent's inode stand in for another's unresolved
path; a cache entry surviving delete-and-recreate; an identity marker that a
reviewer showed to be forgeable; a cached mount root that dangled when the process
it was taken from exited; and \texttt{bind} missing from the mutator table, which
made a socket exchange score only when the scenario's cleanup \texttt{unlink}
supplied the mutator. The last is the case the suite exists for: the first socket
run reported 4 of 8, and the stricter bind-only variant exposed why.
Table~\ref{tab:ablation} shows the trajectory for the first four, and
Appendix~B records each defect with its failing metric.

\paragraph{Operating cost.} We ran a fixed CPU and file workload in a container
five times with the sensor off and five times with it on. Median wall time was
0.949~s and 0.947~s respectively, a difference inside run-to-run noise, so no
slowdown was measurable at this workload. The sensor itself consumed 0.29~s of CPU
while capturing 1,895 events, which is $6.1\%$ of one core over the measurement
window. The probe filters in kernel and emits only modelled syscalls, so cost
tracks interactions observed rather than syscalls issued.
